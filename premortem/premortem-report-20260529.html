Synthesis
Most Likely Failure

Naming conventions collapse assembly at scale

A repository built by multiple engineers over years will have omega_shaft, w_out, and shaft_speed_rpm — semantically identical but physically incompatible (rad/s vs RPM). The LLM guesses port names from summaries. 60%+ cross-engineer connections fail or silently mismatch units. This hits immediately when the repository exceeds one engineer's models.

Most Dangerous Failure

Silent physics errors that ship to customers

Port domain mismatch (Simscape thermal HeatPort connected to a Simulink double signal) and LLM assembly errors (Id/Iq swapped, gear ratio reference inverted) both produce models that simulate without errors, produce plausible-looking numbers, and are wrong by 10–40% in ways that surface only at customer delivery or dyno validation. The damage isn't a broken pipeline — it's a wrong result in a customer report.

The Hidden Assumption — The One That Kills Everything

Semantic similarity of text descriptions is a proxy for physical assembly compatibility

Every single failure mode traces back to this. The entire pipeline assumes that if two component summaries are semantically similar, the components are compatible to assemble. They are not. Physical compatibility is a function of: port domain (Simscape vs Simulink signal), solver contract (continuous/discrete/steady-state), units (rad/s vs RPM), fidelity tier (averaged vs FEM), analysis context (steady-state vs transient), and version (current flux maps vs 2022 flux maps). None of these properties are reliably captured by a short LLM-generated text summary. You are building a search engine but treating it as an assembly planner.

Revised Plan
  1. 1
    Split retrieval from assembly — don't let the LLM wire ports Use semantic search (TurboVec) only for retrieval — finding the right subsystem candidates. Use a separate rule-based port-matching layer for assembly that reads explicit port metadata (domain, units, direction) and only connects ports with verified compatible contracts. The LLM generates the structural intent; a validator enforces physics constraints.
  2. 2
    Add hard structured metadata — not derived from text Before indexing, tag every subsystem with: fidelity_tier (averaged | lookup | FEM | surrogate), analysis_type (efficiency | drive_cycle | torque_accuracy | inefficiency), solver_contract (continuous | discrete | steady_state), and port_schema with domain + units explicitly. These are mandatory fields, not optional. Filter on them first; embed second. Never let a drive_cycle block assemble with a steady_state gearbox regardless of cosine similarity.
  3. 3
    Port canonicalization before indexing Run a one-time normalization pass across the repository: map all shaft speed outputs to a canonical name + unit (e.g., omega_shaft_rads). Document the mapping table. Make this a pre-commit hook so new models must declare their port against the canonical schema before they enter the index. This is infrastructure work — do it before the first production query.
  4. 4
    Automated re-indexing on every model commit Every .slx or .ame commit triggers a re-index of the changed subsystems. The index stores a SHA hash of the source file alongside each embedding. Queries that return a subsystem where the stored hash doesn't match the current file are flagged as stale before retrieval, not after assembly. One person owning re-indexing is a three-month shelfware countdown.
  5. 5
    Assembly validation harness as a mandatory gate After every LLM assembly via model_edit: (a) check that all Simscape thermal loss input ports have nonzero driver signals, (b) verify state count after structural_simplify matches expected count for the fidelity tier, (c) run a 1-second trim and check that no signals are identically zero at a rated operating point where they shouldn't be. This harness catches the silent failures — the Id/Iq swap, the frozen thermal model, the zero iron loss — before results reach an engineer.
Pre-Launch Checklist
  • Port canonicalization table exists and covers all shaft, thermal, and electrical port names across the full repository. Run a grep for all unique port name strings; count how many distinct names exist for "shaft speed output." If more than 1, stop and normalize first.
  • Every subsystem in the index has explicit fidelity_tier, analysis_type, and solver_contract metadata fields — not inferred from text, set as structured tags. Queries must be able to filter on these fields before semantic ranking.
  • Port schema includes Simscape physical domain type, not just port name. Spot-check 5 subsystems: retrieve their TurboVec metadata and verify that Simscape thermal ports are tagged domain: thermal, not type: double.
  • Re-indexing is automated, not manual. A CI hook or file-watcher triggers re-index on .slx/.ame changes. Confirm the index SHA matches current file SHAs for all models before going live.
  • Assembly validation harness passes on 3 known-good manually assembled models before trusting it on agent-assembled outputs. If it can't detect a known fault (e.g., a deliberately swapped Id/Iq), it won't catch the LLM's version either.

Agent 1

Embedding Space Collapse — FEM vs Averaged Motor Indistinguishable

The high-fidelity FEM motor and the averaged quasi-static motor both got the summary: "a PMSM subsystem that computes torque and back-EMF from dq currents." Cosine distance 0.05. The agent retrieved the quasi-static motor for an efficiency query, assembled it, and the simulation ran for three weeks before someone noticed iron losses were zero and thermal states were absent.
Underlying Assumption
Short natural-language summaries preserve physically meaningful distinctions between simulation fidelity levels.
Early Warning Signs
Two components with 6 vs 60 blocks return cosine similarity above 0.90. Assembled model's state count after structural_simplify is lower than expected.
Agent 2

Port Domain Mismatch — Simscape HeatPort Wired to Simulink Double

Both subsystems had a port named T_motor — one was a Simscape thermal connection, the other a plain Simulink double in Celsius. The LLM matched by name. Simulink accepted the wire. The thermal states never updated. The model ran at 25°C throughout six months of efficiency validation. The failure surfaced during a drive cycle that pushed the motor to 140°C.
Underlying Assumption
Port name equality implies physical domain compatibility and solver contract compatibility.
Early Warning Signs
TurboVec metadata shows type: "double" for every port with no domain field. First model_edit assembly produces no error but downstream sim() fails with an opaque algebraic loop diagnostic.
Agent 3

Fidelity Mismatch — Iron Loss Input Port Unconnected, Silently Zero

The agent assembled a high-fidelity 11-node thermal model with an averaged EM model. The thermal model computed iron losses from a flux density input port that was never connected — the averaged EM model had no such output. It defaulted to zero. Iron loss temperature rise was absent. Winding temperature error at high-speed light-load: 22°C. Caught only at Motor-CAD validation, six months in.
Underlying Assumption
Semantic similarity of component descriptions is a sufficient proxy for physical interface compatibility.
Early Warning Signs
Assembled models simulate without errors but contain unconnected thermal loss input ports. Iron loss channel in logged output is identically zero across all operating points above 1000 RPM.
Agent 4

Parameter Drift — Stale Index Returns 2022 Gearbox with Gen3 Motor

The index was last rebuilt in February. The Gen3 motor team pushed three flux map updates and revised d-axis inductance by 11%. The gearbox retrieved alongside it was from a 2022 efficiency campaign, before the Gen3 ratio change. The simulation produced clean results. Engineers shipped efficiency numbers to a customer. Dyno results showed 4% lower efficiency. Tracing the version required two days of manual .slx binary diffing.
Underlying Assumption
A model's identity is stable once named, so a match on semantic description implies a match on current parameter values.
Early Warning Signs
Index modification timestamp drifts more than 2 weeks behind the repo's latest commit. Two engineers querying the same component get different simulation results because they're on different index versions.
Agent 5

Maintenance Burden — Shelfware in 3 Months

The designer got pulled onto a vehicle program. Re-indexing lived only in a README. Engineers started getting stale results — deprecated single-node inverter thermal model instead of the current one. Word spread: "the agent gives you old stuff." Usage dropped to near zero within weeks. The index was never formally deprecated. It sat there, increasingly wrong, until the server was repurposed.
Underlying Assumption
Initial accuracy is durable. In reality, a retrieval system is only as trustworthy as its worst recent staleness event.
Early Warning Signs
Re-indexing step has no CI hook or cron job — it lives only in one person's README. A query returns a subsystem description referencing a port name that was renamed more than two weeks ago.
Agent 6

Case-Type Metadata Lost — Steady-State Gearbox Assembled with Transient Motor

A query for "high-fidelity IPMSM with planetary gearbox for vehicle efficiency study" returned an IPMSM from the drive cycle folder and a gearbox from the efficiency folder. Both said "high-efficiency." Neither said "I expect a fixed operating point" or "I need a 1200-second transient profile." Efficiency values varied by 3–5% depending on where in the drive cycle the snapshot was taken. A hardware team sized a cooling system from these numbers.
Underlying Assumption
Semantic similarity of component descriptions implies compatibility of operational context and solver contract.
Early Warning Signs
Assembled model has inconsistent solver settings between subsystems. Efficiency values vary by more than 3–5% depending on snapshot location in the drive cycle — a result that would be constant if both components were steady-state compatible.
Agent 7

LLM Assembly Hallucination — Id/Iq Swapped, Gear Ratio Inverted

The LLM swapped Id and Iq ports because both were described as "electrical ports carrying dq-frame current." Copper losses ran 40% low for six weeks of thermal validation. Separately, the gear ratio reference shaft was wired as output instead of input — reflected inertia was wrong by 85x (ratio²). The NVH team spent three weeks chasing what looked like a damping coefficient error in their upstream model.
Underlying Assumption
A model that simulates without error and produces plausible steady-state results is physically correct.
Early Warning Signs
Steady-state values match but transient response time constants are inconsistent with known component inertias by more than 20%. Copper loss at a known operating point disagrees with the datasheet lookup table by more than a few percent.
Agent 8

Naming Convention Chaos — shaft_speed_rpm vs omega_shaft at Scale

omega_shaft, w_out, shaft_speed_rpm — three engineers, three names, one a units error (RPM vs rad/s). The LLM matched by name fragment and generated connection code with 60%+ cross-engineer failure rate. The RPM/rad/s mismatch (factor of 2π/60) produced gearbox output torques 10x too low. No assertion caught it. Discovered at the third integration cycle. The system was quietly deprecated after producing unvalidatable results.
Underlying Assumption
Port names are stable, unique identifiers for physical quantities — but they are free-form strings with no enforced contract between name, units, and physics.
Early Warning Signs
First integration test across two different engineers' subsystems fails or produces a wrong result. TurboVec metadata for semantically equivalent ports returns more than one distinct name string — measurable before any assembly is attempted.
