Motivation

Every Simscape modeling session produces .slx files that no future agent can find or reuse. Port names are inconsistent. Domain mismatches cause silent wiring errors. Fidelity variants (FEM ↔ averaged) are invisible to a search engine. The result: every agent rebuilds from scratch, makes the same mistakes, and produces one-off artifacts that never compound.

SimVault solves this with three interlocking mechanisms:

🔍 Semantic Search

ChromaDB + BGE embeddings find the right component by description, fidelity, and analysis type — even when port names differ.

🕸 Knowledge Graph

NetworkX tracks which ports are compatible, which models are fidelity variants of each other, and which thermal inputs need EM sources.

⚡ Wire Validator

PASS / WARN / BLOCK for every proposed connection — domain mismatches, unit scale errors, solver contract violations.

🤖 MCP Interface

4 tools that Claude agents call before any model_edit call — guaranteed physically-valid assembly context.

The meta-test (T9)
Agent A (multi-agent workflow) → builds FEM_IM_FOC_MA.slx.
SimVault → indexes it automatically.
Agent B (future session) → finds it via simvault_search, assembles a new model reusing that exact subsystem.

If T9 passes, every agentic build enriches the shared library — work compounds.

Data flow

  ├─ MATLAB: extract_metadata() → extracted/*.json
  ├─ Python: canonicalize_all() → extracted/*.json (ports updated) + kb/models/*.md
  ├─ Python: build_graph()     → simvault.graph.json
  └─ Python: build_index()     → .svdb/ (ChromaDB)

simvault query "PMSM thermal"
  ├─ ChromaDB: embed + cosine search → seed_ids
  ├─ NetworkX: expand via compatible_with, fidelity_chain edges
  ├─ validate_wire() on each compatible_with pair
  └─ QueryResult { candidates, subgraph, validated_wires, blocked_pairs }

Parser — extract_metadata.m

The only MATLAB component. Everything downstream is pure Python.

What it does

  • Crawls a directory for .slx files (recursive, skips slprj and _archive)
  • Computes SHA-256 via shasum -a 256 and skips unchanged files (lock file)
  • Loads each model, finds the tagged subsystem, extracts one entry per .slx
  • Detects ports from: top-level Inport/Outport blocks + SL2PS_* / PS2SL_* bridge blocks + sensor subsystems
  • Saves to extracted/<model_name>.json

Port detection logic

SourcePort nameDirection
Top-level Inport blockBlock nameinput
Top-level Outport blockBlock nameoutput
SL2PS_* block (any depth)Block name minus prefixinput
PS2SL_* block (any depth)Block name minus prefixoutput
TPS, SpeedPS, Tem_*Block nameoutput

SimVault Description tags

Add these to a subsystem's Description field in Simulink:

fidelity_tier: detailed
analysis_type: torque_accuracy
solver_contract: continuous

The parser searches all subsystems for a Description containing fidelity_tier and uses that block's tags for the model entry. If none found, infers fidelity from block count.

Canonicalizer — canonicalize.py

Maps original_name → canonical_name using regex patterns. The canonical vocabulary is the shared language that makes the graph's compatible_with edges meaningful.

from simvault.canonicalizer.canonicalize import canonicalize_port

port = {"original_name": "Rotor_Iron_Loss", "units": "W", "direction": "input"}
result = canonicalize_port(port)
# result["canonical_name"]  == "loss_iron_W"
# result["canonical_units"] == "W"
# result["canonicalized"]   == True

Markdown spec output

Each subsystem gets a kb/models/<model>_<subsystem>.md file with:

  • YAML frontmatter: fidelity_tier, analysis_type, solver_contract, source_hash, block_count
  • Port interface table with canonical names and canonicalization status
  • Compatibility alerts (unmatched loss inputs, unit mismatches)

Fidelity stem matching

Strips known suffixes before comparing: _fem, _avg, _averaged, _lut, _nn, _simplified, _detailed, _hifi, _reduced. So PMSM_FEM and PMSM_avg share the stem PMSM → fidelity_chain edge.

Vector Store — index.py

Uses ChromaDB (persistent) with BAAI/bge-small-en-v1.5 embeddings (384-dim cosine). Each subsystem is embedded as a rich document:

doc = f"{causal_summary} | Model: {name} | Fidelity: {fidelity_tier} | "
      f"Analysis: {analysis_type} | Solver: {solver_contract} | "
      f"Canonical ports: {canonical_names} | Port names: {original_names}"

Incremental re-index: compares source_hash in collection metadata and skips unchanged entries. Re-indexing a directory with no changes completes in <3s.

Hard filters

ChromaDB where clauses enforce hard filters before semantic ranking — a query with fidelity_tier=detailed will never return a simplified model, regardless of similarity score.

Validator — validate_ports.py

Four rules, evaluated in order. First failure wins.

#RuleResultExample
1Domain must match BLOCK thermal → signal: cannot cross domain boundary
2Direction must be compatible (input↔output or bidirectional) BLOCK output → output
3Units must match or have a known conversion WARN or BLOCK rad/s → rpm: WARN + Gain(0.1047). W → kW: WARN + Gain(0.001).
4Solver contract must match WARN continuous ↔ discrete: WARN + Rate Transition block required 
from simvault.validator.validate_ports import PortSpec, validate_wire

src = PortSpec(domain="signal", direction="output", canonical_units="rad/s")
dst = PortSpec(domain="signal", direction="input",  canonical_units="rpm")
result = validate_wire(src, dst)
# result.result              == "WARN"
# result.required_bridge_block == "Gain (factor: 9.549...)"
# result.gain_factor           == 9.5493...

Query Engine — query.py

Algorithm

  1. Hard filter — ChromaDB where clause by fidelity/analysis/solver
  2. Semantic search — top-K by cosine similarity
  3. Graph expansion — from each seed subsystem: include port nodes → follow compatible_with → include partner subsystems and their ports
  4. Wire validation — call validate_wire() on every compatible_with pair in the subgraph
  5. Return — QueryResult with candidates, subgraph, validated_wires, blocked_pairs
from simvault.query.query import query

result = query(
    "high-fidelity PMSM thermal",
    fidelity_tier="detailed",
    top_k=5,
)
# result.candidates[0].subsystem_id == "MotorThermal11Node"  ← #1 after corpus enrichment
# "MotorThermal11Node" in result.subgraph.nodes
# len(result.validated_wires) >= 72

Signal Naming Guide — Getting the Best from SimVault

The canonicalizer matches on port names. The better your model's port names, the richer the graph and the more accurate the assembly context. This is the highest-leverage improvement you can make to your corpus.

Key insight — validated empirically
Every named Inport/Outport block becomes a port in the graph. Every graph port can generate compatible_with edges. More named ports → more edges → better agent assembly. Enriching 6 models increased compatible_with edges by 50% and corrected query ranking for both thermal and induction motor searches.

Recommended practices

1. Add named Inport/Outport blocks at the model boundary

In your top-level model, replace numbered ports with named ones:

SignalGood nameBad nameCanonical
Shaft speed outomega_shaft_radsOut1omega_shaft_rads
Electromagnetic torquetorque_shaft_Nm2torque_shaft_Nm
Copper loss to thermalloss_copper_Wsignal_outloss_copper_W
Iron loss to thermalloss_iron_WOut3loss_iron_W
d-axis currentidinput_1id_current_A
q-axis currentiqinput_2iq_current_A
DC bus voltageVdcDC_invdc_V

2. Use SL2PS_/PS2SL_ naming for Simscape physical bridges

The parser auto-detects these patterns — the block name becomes the port name:

SL2PS_Copper_Loss    → port "Copper_Loss"  → canonical loss_copper_W  (input)
SL2PS_Iron_Loss      → port "Iron_Loss"    → canonical loss_iron_W    (input)
PS2SL_AirGap         → port "AirGap"       → canonical temperature_K  (output)
PS2SL_Stator_Temp    → port "Stator_Temp"  → canonical temperature_K  (output)

3. Add port unit and domain tags to the subsystem Description

fidelity_tier: detailed
analysis_type: torque_accuracy
solver_contract: continuous
units_omega_shaft_rads: rad/s
domain_omega_shaft_rads: signal
units_loss_copper_W: W

4. Write a good causal summary in the Description

The first non-tag line becomes the embedding document's summary — it's what semantic search uses. Make it descriptive:

FEM-based IPMSM motor model with torque accuracy at full speed range.
fidelity_tier: detailed
analysis_type: torque_accuracy
solver_contract: continuous

This is better than just leaving the Description empty or using only tags.

5. Name fidelity variants consistently

SimVault detects fidelity_chain edges by stem-matching. Keep your variant names consistent:

PMSM_FEM.slx   + PMSM_avg.slx     → stem "PMSM" → fidelity_chain ✓
FOC_detailed.slx + FOC_simplified.slx → stems differ → no edge ✗
FOC_FEM.slx    + FOC_avg.slx      → stem "FOC"  → fidelity_chain ✓
